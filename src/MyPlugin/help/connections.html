접속

연결 > 접속 관리…에서 접속을 추가·복제·삭제·편집하고 [접속 테스트]로 확인합니다. 비밀번호는 이 PC의 이 Windows 사용자만 풀 수 있게(DPAPI) 저장하며, 저장하지 않고 연결 때마다 입력할 수도 있습니다. 색 표시(개발 초록 · 검증 노랑 · 운영 빨강)는 탭·트리·확인 창의 배지에 쓰입니다.

SQL Server 암호화·인증서

SQL Server를 고르면 [암호화](필수 · 엄격(TDS 8.0, SQL Server 2022 이상) · 선택), [서버 인증서 신뢰], [인증서 이름] 칸이 보입니다. 새 접속은 암호화 필수 + 서버 인증서 검증이 기본입니다. 사내 자체 서명 인증서라 [접속 테스트]가 "서버 인증서를 신뢰할 수 없습니다"로 실패하면 [서버 인증서 신뢰]를 직접 켜세요(검증을 하지 않으므로 운영 접속에는 신뢰할 수 있는 인증서를 권장). 인증서의 이름이 접속 호스트와 다르면(IP로 접속 등) [인증서 이름]에 인증서의 이름을 넣습니다. 엄격은 신뢰 설정과 관계없이 항상 검증합니다.

이 설정이 생기기 전에 저장한 SQL Server 접속은 갑자기 붙지 못하지 않도록 이전 동작(암호화 선택 + 서버 인증서 신뢰)으로 읽고, 접속 관리에 강화를 권하는 안내를 노랗게 보입니다. [암호화]를 필수로 바꾸고 인증서를 검증하도록 고친 뒤 [접속 테스트]로 확인하세요. 오류 문장에는 비밀번호를 남기지 않습니다.

취소

[취소]는 실행 중인 명령에 취소를 보냅니다. Oracle은 in-band break를 씁니다(기본 OOB는 Docker Desktop·일부 방화벽·NAT를 지나지 못합니다). 취소된 실행은 오류로 끝나고 세션은 계속 쓸 수 있습니다.

세션 규칙

  • DB마다 세션 1개. 같은 DB의 탭들은 트랜잭션을 함께 쓰고, 한 번에 한 문장만 실행합니다.
  • 연결을 끊거나 창을 닫을 때 커밋 대기가 있으면 물어봅니다.
  • 저장된 접속 정보를 바꿔도 열린 세션은 원래 DB에 붙어 있습니다. [다시 연결]하면 적용됩니다(읽기 전용을 켠 것만 바로 적용).
