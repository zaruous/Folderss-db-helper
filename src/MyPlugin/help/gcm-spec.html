GCM(공통 코드) 정의서

공통 코드 테이블을 읽는 SELECT 문을 직접 쓰고, 결과 열의 AS 별칭만 계약에 맞추면 엑셀·JSON·CSV 정의서를 만듭니다. 플러그인은 SQL을 해석하지 않으므로 환경마다 테이블·열 이름이 달라도 SQL만 바꾸면 되고, Oracle·PostgreSQL·SQL Server 어디서나 됩니다. 도구 > GCM 정의서 만들기…(트리에서 고른 DB) 또는 트리의 DB 행 오른쪽 메뉴.

순서

  1. 창 머리의 [대상 DB]를 확인합니다. 다른 접속을 고르면 창을 닫고 그 DB로 다시 엽니다(편집기의 SQL은 가져감).
  2. SQL을 쓰거나 [저장한 SQL]에서 고릅니다. .sql 파일을 편집기에 끌어다 놓아도 되고, [본보기 SQL]로 플러그인의 본보기(범용 코드 테이블 꼴)를 넣어 고쳐도 됩니다.
  3. [열 확인]: SQL을 한 행만 읽게 감싸 실행해 별칭 표에 있음·빠짐을 표시합니다(큰 조회도 빠릅니다).
  4. 문서 정보와 출력 형식(엑셀 양식 · JSON · CSV)을 고르고 [만들기…]. 저장 위치를 물은 뒤 조회 → 별칭 검사 → 그룹 묶기 → 출력합니다.

  • 대소문자는 구분하지 않습니다. 바인드 변수는 받지 않습니다(값을 직접 적습니다). 끝의 ;·/ 줄은 떼어 냅니다.
  • 그 밖의 열은 모두 추가 속성이 되어 양식의 ${code.attrs.열이름}·${code.attrText}("이름=값; …"), JSON의 attrs, CSV의 뒤쪽 열에 들어갑니다.
  • 그룹은 TABLE_NAME이 같은 행을 처음 나온 순서로 묶습니다. 그룹 명칭·설명은 그 그룹에서 처음 비어 있지 않은 값입니다.

코드 테이블마다 열 이름이 다른 구조 (이름/값 짝 열)

정의 테이블이 열 이름을 정하고 데이터 테이블이 값을 담는 범용 코드 테이블은 이름 열과 값 열을 짝으로 나열합니다. 추가 열 X와 X_NAME이 함께 있으면 행마다 X_NAME의 값이 속성 이름, X의 값이 속성 값이 됩니다. 이름이 비어 있는데 값이 있으면 값 열 이름(DATA_2)이 속성 이름이 되고, 둘 다 비면 뺍니다. 평범한 열 나열이라 어떤 DBMS에서나 같은 SQL입니다.

본보기 SQL 전문은 창의 [본보기 SQL] 버튼으로 편집기에 넣어 보세요. 사내 코드 테이블 구조가 담겨 있어 도움말·문서에는 싣지 않고 플러그인 안에 잠가 둡니다.

본보기는 정의 테이블이 없는 그룹도 남도록 LEFT JOIN이고, 공장(사이트)은 첫 것 하나만 고릅니다(환경마다 코드가 달라 고정값은 0행이 되기 쉽습니다. 특정 공장은 WHERE에 직접 적으세요). 예를 들어 그룹 ORDER_STATUS의 코드에는 STATUS·SHIP_FLAG처럼 그 그룹의 열 이름이 속성이 됩니다. 기본 양식의 그룹 시트는 머리글에 그 그룹의 속성 이름을 적고 칸에 "이름=값; …"을 넣습니다. 양식에서 열을 따로 두려면 $group.attrNames·$code.groupAttrValues를 씁니다. 문자열 잇기 ||는 Oracle·PostgreSQL에서 되고 MySQL은 CONCAT, SQL Server는 +입니다.

JSON 객체 열(PostgreSQL jsonb_build_object 등)도 같은 식으로 키를 펼치지만 DBMS 고유 함수라 선택 사항입니다.

저장한 SQL과 그룹 정규식

  • [저장…]은 편집기의 SQL을 SQL 폴더(플러그인 데이터 폴더의 code-sql)에 .sql로 저장합니다. 이 폴더의 파일이 [저장한 SQL] 목록에 보이고, 접속마다 마지막에 쓴 파일을 기억합니다. [SQL 폴더]로 탐색기에서 엽니다.
  • [LLM에게 SQL 요청]은 별칭 계약이 든 요청 글을 복사합니다. 우리 테이블 구조를 덧붙여 LLM에게 보내면 맞는 SQL을 써 줍니다.
  • 그룹 정규식으로 TABLE_NAME(옵션: 그룹명·설명도)를 걸러 일부 그룹만 넣습니다. 예: ^ORDER_, STATUS$. 비우면 모두.
  • 조회가 0행이거나 정규식에 맞는 그룹이 없으면 정의서를 만들지 않고 상태 줄에 이유를 보입니다(빈 문서가 나오지 않게). WHERE의 공장 코드 등을 확인하세요.

양식 변수 요약

$doc(title·project·system·author·version·date·description·groupCount·codeCount·generatedAt), $db(name·user·address·version), $source(name·sql·fetchedAt·rowCount·columns·attrNames·expandedColumnsText), $groups → $group(no·id·name·description·sheetName·codeCount·codes·attrNames), $codes → $code(no·group·groupName·code·name·description·sortNo·useYn·isUsed·attrs·attrValues·groupAttrValues·attrText). 셀에 ${group.id}처럼 쓰고 #foreach … #end 줄로 되풀이하며, 그룹마다 시트는 시트 맨 위 #sheet($group in $groups). 전체 목록은 양식의 _변수 설명 시트.

알아 둘 점

  • 조회는 모든 행을 메모리에 올립니다. 그룹이 아주 많으면 그룹별 시트 양식 대신 단일 시트 양식이나 그룹 정규식을 쓰세요.
  • PostgreSQL에서는 조회 결과를 열어 둔 채 정의서를 만들면 그 결과의 [다음 행 가져오기]가 꺼집니다(연결당 커서 하나).
  • 표지의 DBMS 버전은 서버에서 읽어 넣습니다(읽지 못하면 빈 칸).
