성능 모니터

도구 > 성능 모니터…(트리에서 대상 DB를 고른 뒤) 또는 트리의 DB 행 오른쪽 메뉴에서 엽니다. 트리에서 연결하지 않아도 됩니다. 창은 모달이 아니라 열어 둔 채 SQL을 쓸 수 있고, DB마다 하나만 뜹니다(같은 DB에서 다시 열면 그 창이 앞으로).

  • 섹션은 처음 고를 때 가져옵니다. [새로 고침](F5)과 자동 새로 고침(끔 · 5초 · 15초 · 60초)은 보고 있는 섹션만 다시 가져옵니다.
  • 저장 공간 섹션(Oracle 테이블스페이스 · SQL Server 데이터 파일)은 표 위 대시보드에 행마다 사용률 도넛 차트를 그립니다(가운데 %, 아래 이름과 사용/전체 MB). 80% 이상은 경고색, 90% 이상은 위험색이고 최대 12개까지 보인 뒤 나머지는 "외 N개는 표에서"로 알립니다. PostgreSQL 테이블스페이스는 한도가 없어 차트가 없습니다.
  • 저장 공간 섹션에서 표의 행이나 도넛을 누르면 표 아래(분할선으로 크기 조절)에 상세 목록이 뜹니다. Oracle은 [데이터 파일](파일·크기·자동 확장·최대·증가·상태)과 [세그먼트](DBA_SEGMENTS — 테이블·인덱스·LOB, 파티션은 이름으로 합쳐 큰 것부터 200개), PostgreSQL은 그 테이블스페이스에 저장된 객체(현재 DB), SQL Server는 그 파일이 속한 파일 그룹의 객체(파일 단위로는 나뉘지 않음, 로그 파일은 비어 있음)입니다.
  • 잠금·세션 섹션에서 행을 누르면 아래에 [SQL 전문]·[실행 계획]·[세션 정보/통계]가 보입니다. SQL 전문과 실행 계획은 표가 아니라 글 상자라 그대로 복사할 수 있습니다. Oracle은 V$SQL·DBMS_XPLAN.DISPLAY_CURSOR(세션이 쉬는 중이면 직전 문장)·V$SESSTAT, SQL Server는 sys.dm_exec_sql_text(쉬는 세션은 마지막 문장)·sys.dm_exec_text_query_plan(실행 중일 때만, XML), PostgreSQL은 pg_stat_activity.query(서버가 track_activity_query_size 기본 1,024자까지만 보관)와 세션 정보이고 다른 세션의 실행 계획은 주지 않습니다.
  • 잠금 연쇄 트리(지금은 Oracle): [잠금] 섹션은 누가 누구를 막는지 근원 블로커를 맨 위에 두고 막힌 세션을 그 아래에 펼칩니다(GV$SESSION.BLOCKING_SESSION — 행 잠금뿐 아니라 라이브러리 캐시 핀처럼 다른 세션을 기다리는 대기도). 위 줄에 "근원 2 · 막힌 세션 5 · 최장 대기 4분 12초"처럼 요약하고, 근원 줄에는 막은 세션(아래 전체)과 유발 대기(아래 세션들이 기다린 시간의 합)를 보입니다. 근원은 대개 커밋하지 않고 쉬는 세션이라 유휴(초)·트랜잭션 시작 시각·직전 SQL_ID를 함께 보이고, 행을 누르면 [SQL 전문]에 직전 문장이 나옵니다. 최소 대기(기본 3초, 전부 · 3 · 10 · 30 · 60초)보다 사슬 안의 가장 긴 대기가 짧으면 그 사슬을 통째로 숨깁니다(다시 조회하지 않음). 서로 막는 순환(교착)은 ⟳ 묶음으로 따로 보입니다. 오른쪽 메뉴 [근원 세션 종료…]는 고른 줄이 속한 사슬의 근원을, [세션 종료…]는 그 줄의 세션을 끊습니다(ALTER SYSTEM KILL SESSION 'sid,serial#,@인스턴스' IMMEDIATE — RAC의 다른 인스턴스 세션도). [표로 보기]는 잠금 모드(TM·TX, 보유·요청 모드)까지 보이는 지금까지의 표로 바꿉니다. 열 머리로 정렬하면 트리 모양이 흐트러지니 세 번 눌러 원래 순서로 돌아오세요.
  • 표의 오른쪽 메뉴 [세션 종료…]는 고른 행의 세션 번호로 ALTER SYSTEM KILL SESSION 'sid,serial#' IMMEDIATE · SELECT pg_terminate_backend(pid) · KILL n을 만들어 문장·경고·확인 체크 대화상자를 거친 뒤 실행하고 섹션을 다시 가져옵니다. 그 세션의 커밋하지 않은 변경은 롤백되고 사용자는 끊깁니다. 읽기 전용 접속에서는 막히며, Oracle은 ALTER SYSTEM 권한이 있어야 합니다.
  • 표는 결과 그리드와 같아 열 머리로 정렬하고 Ctrl+C·오른쪽 메뉴로 복사합니다. 섹션 하나는 최대 2,000행까지 가져옵니다.
  • 모니터 창은 전용 세션을 따로 엽니다. SQL 탭의 세션·트랜잭션과 무관해서, SQL 탭에서 긴 문장을 실행하는 중에도 모니터는 기다리지 않고, 자동 새로 고침이 SQL 탭 실행을 막지도 않습니다. 저장된 비밀번호가 없으면 모니터를 처음 가져올 때 한 번 묻습니다. DB 쪽 세션이 하나 늘어나며, 세션 목록에 이 창의 세션도 보입니다. 창을 닫으면 그 세션도 닫힙니다. 자료를 바꾸는 문장은 [세션 종료…]뿐입니다.
  • 상태 글에 조회 시간(예: "· 0.8초")이 붙습니다. 행 상세는 같은 행을 다시 누르면 다시 조회하지 않고 보관한 결과를 보입니다("· 캐시"). 섹션을 새로 고치면 비웁니다.
  • 확장 설치나 서버 버전이 필요한 섹션(지금은 PostgreSQL 느린 SQL의 pg_stat_statements·13 이상)은 가져오기 전에 점검해, 안 되면 조회하지 않고 "설치·설정 필요 — …"를 주황색으로 보입니다. 무엇을 어떻게 설치해야 하는지(shared_preload_libraries → 재시작 → CREATE EXTENSION)가 그 글에 있습니다. 권한 오류(빨강)와는 다른 색입니다. 접속이 이 PC(localhost · 127.0.0.1 · 컴퓨터 이름)의 서버면 직접 설치할 수 있으므로, 단계별 절차와 문서·내려받기 링크를 DB Helper 메시지 탭에 함께 남깁니다(원격 서버는 관리자에게 전달해야 하므로 남기지 않음).
  • 권한이 없는 섹션은 그 섹션만 "권한이 없어 가져오지 못했습니다 — 필요 권한: …"으로 보이고 다른 섹션은 그대로 동작합니다.

전체 DB 상태

도구 > 전체 DB 상태…는 저장한 접속마다 타일 하나를 보입니다(지금은 Oracle — PostgreSQL·SQL Server 타일은 "지원 예정"). 타일 머리 띠는 접속 색, 오른쪽 위는 상태, 그 아래 줄은 왜 그 상태인지(가장 심각한 것 하나)입니다.

  • 판정(주의/위험): 잠금 대기 세션 1/5개 또는 최장 대기 60/300초(3초 이상 기다린 세션만), 공간 85/95%(자동 확장 최대 크기 기준, 영구 테이블스페이스만), FRA 80/90%(회수 가능 공간 제외), 아카이브 대상 오류(위험), 마지막 백업 26/50시간(기록이 없으면 주의), 평균 활성 세션이 CPU 수의 1/2배, 최근 24시간 실패한 예약 작업(주의).
  • 위험 → 접속·조회 실패 → 주의 → 권한 필요 → 비밀번호 필요 → 정상 → 지원 예정 순서로 놓고(정렬을 이름으로 바꿀 수 있음), 오른쪽 메뉴 [맨 앞에 고정]한 타일은 늘 맨 앞입니다. [이 화면에서 빼기]한 접속은 머리의 [숨긴 DB 다시 보이기]로 돌아옵니다. 고정·숨김은 다음에 열어도 남습니다.
  • 타일을 누르면 그 DB의 성능 모니터가 열리고, [잠금 트리 열기]는 [잠금] 섹션으로 바로 엽니다.
  • 타일마다 이 창 전용 세션을 열어 창이 열린 동안 유지합니다(동시 4개, DB마다 10초 제한, 창을 닫으면 정리). 저장된 비밀번호가 있는 접속만 스스로 붙고, 없으면 "비밀번호 필요" 타일을 누를 때 묻습니다.
  • 자동 새로 고침은 끔 · 30초 · 1분(기본) · 5분, F5는 지금 새로 고침. 미니 추이는 평균 활성 세션(60초 평균)이고 창이 열린 동안만 쌓입니다. 창이 닫혀 있으면 감시하지 않습니다.
  • 머리의 [일일 점검…]은 아래 일일 점검 창을 엽니다.

일일 점검

도구 > 일일 점검…(또는 전체 DB 상태의 [일일 점검…])은 고른 DB들에 아침 점검 항목을 한 번에 돌려 항목마다 정상 · 정보 · 주의 · 위험 · 건너뜀 · 오류와 값, 직전 대비(처음 · 같음 · ↑ 나빠짐 · ↓ 좋아짐)를 보이고, 엑셀 보고서로 저장합니다(지금은 Oracle — PostgreSQL·SQL Server는 "지원 예정").

  • 왼쪽에서 대상 DB를 고르고 [점검 실행](F5). 처음에는 저장된 비밀번호가 있는 접속이 골라져 있고, 다음부터는 마지막에 고른 DB입니다. 비밀번호가 없는 DB는 실행할 때 하나씩 묻습니다. DB마다 점검 전용 세션을 열고 끝나면 닫습니다(동시 4개).
  • Oracle 기본 항목(17개): 인스턴스 상태 · 아카이브 로그 모드 · 아카이브 대상 오류 · 테이블스페이스 사용률(자동 확장 최대 기준 85/95%) · FRA(회수 가능 제외 80/90%) · 마지막 성공 백업(26/50시간, 기록 없음은 주의) · 실패·경고 백업 · 경고 로그 ORA- 오류 · 시간당 로그 스위치(12/30회) · INVALID 객체 · UNUSABLE 인덱스·파티션 · 오래된 통계 · 실패한 스케줄러 작업 · 중단된 DBMS_JOB · 30분 넘게 실행 중인 세션 · 잠금 대기(60/300초) · 14일 안에 만료되는 비밀번호. 내장 스키마(SYS·APEX_… 등)는 뺍니다.
  • 권한이 없어 못 본 항목은 건너뜀과 필요 권한, 조건이 안 맞는 항목(FRA를 쓰지 않음 등)은 건너뜀과 이유를 보입니다. 11g~12.1의 경고 로그(V$DIAG_ALERT_EXT)는 SELECT_CATALOG_ROLE로 보이지 않아 SYS가 따로 허용해야 돕니다. 항목 하나는 60초를 넘으면 오류로 끝나고 다음 항목으로 넘어갑니다.
  • 항목 줄을 누르면 아래에 값·판정 기준·직전 상태·필요 권한과 조치 안내(주의·위험) 또는 이유(건너뜀·오류), [SQL 보기]·[SQL 복사], 발견 행(최대 100행)이 보입니다.
  • 기록: 점검할 때마다 항목별 상태·값·행 수만 플러그인 데이터 폴더의 monitor-history\history.db에 남깁니다(발견 행 — 객체·사용자 이름 같은 DB 내용 — 은 남기지 않습니다). DB는 서버가 알려 주는 식별(DBID·이름)로 구분하므로 접속 이름을 바꿔도 직전 대비가 이어집니다. 설정 > 성능 모니터에서 기록을 끄거나 보관 기간(기본 90일)을 바꾸고, 이력을 지울 수 있습니다.
  • [엑셀로 저장…]: 기본 양식은 요약 시트(DB별 상태 수 · 주의 이상 항목)와 DB마다 시트(항목 표 · 발견 사항)입니다. [양식 ▾]에서 기본 양식을 파일로 저장해 고친 뒤 내 양식으로 고를 수 있습니다(문법은 테이블 정의서와 같고, 변수는 양식의 _변수 설명 시트에 있습니다). 저장한 파일은 저절로 열지 않고 [열기]로 엽니다.
  • [항목 관리…]: 기본 항목을 끄거나(개발 DB의 로그 모드 등) 임계값 문턱을 바꿉니다(모든 DB에 적용). 사용자 항목은 SELECT 한 문장과 판정(행이 있으면 주의/위험 · 열의 최댓값과 문턱 · 판정 열의 OK·WARN·CRIT · 정보)으로 만들고, [시험 실행]으로 고른 DB에 한 번 돌려 결과와 판정 열 후보를 봅니다. [내보내기…]·[가져오기…]는 JSON 파일 하나로 팀에 나눕니다(같은 id는 덮어쓸지 묻습니다).
  • 창이 닫혀 있으면 정해진 시각에 저절로 돌지 않습니다.
